# 6.2.0 迭代：同语义处理收敛与精简开发规范

## 目标与授权

将本轮讨论落到 `my-agent-skills` 插件：开发时主动发现已有能力，在第二份同语义实现出现前后判断并完成适当收敛；让 handler 注释承担局部契约与逻辑说明，统一开发规范保持精简并能被新会话找到。

用户已确认：同类逻辑在两处及以上需要处理；泵频与设备状态属于不同职责，应独立为两个 handler；规范保持精简，handler 注释承担部分文档任务。随后明确要求先整理迭代文档，再开启 Goal 推进执行。本文件为该轮迭代的开发说明与唯一执行队列。

本次执行对象是此插件仓库的工作流规则和回归证据。机柜会话提供现实场景；本迭代不直接修改其业务项目。交付终点为可审阅的源码变更、完成的相关验证及诚实记录的限制；不包含发布、安装或向其他会话发送消息。

## 已接受的设计

1. **两份实现触发判断。** 已存在或即将新增第二份相同业务规则的实现，就检查已有归属和消费者；同一 helper 有多个调用不构成重复实现。
2. **语义一致默认收敛。** 比较用途、输入输出、缺失/异常语义及是否应同步变化。优先扩展已有入口；必要时提取最小共享实现。只迁移本任务涉及的调用者，清理经验证已被替代的重复逻辑。
3. **例外有明确理由。** 语义不同，或共享会破坏依赖/发布边界时保留独立实现并简述原因。重复次数不授权改变业务规则、越过架构分流或扩大清理范围。
4. **不同职责独立 handler。** 泵频展示与设备状态分别归属。必要的底层原语可复用，但不得用大量场景开关将不同领域政策拼成万能工具。
5. **注释承担局部文档。** 清晰名称包含领域检索词；短注释解释用途、非显然的契约、单位/缺失值、关键规则与设计原因，必要时链接既有权威规格或测试。避免逐句翻译代码。
6. **规范承担导航与约束。** 复用项目已有开发规范，只保留职责、首选入口及跨模块约束，链接 handler 代替复制细节。`AGENTS.md` 只放简短适用说明与阅读指向；新会话按任务读相关章节和源代码。
7. **只沉淀稳定经验。** 用户明确要求或已接受工作形成可复用约定时更新既有规则；替换过时说明，避免任务历史、未接受建议、每个 helper 的登记册及重复条目进入长期规范。
8. **流程与开销适度。** 必要的局部提取可以随已授权功能一起交付，验证原有行为与请求变化；无关重构保持独立。无新增 Skill、默认发现描述、运行时脚本、依赖或通用审批门禁。

## 行为验收

- 两个实际消费者执行相同规则时，能优先找到已有入口；没有现成入口时可进行有证据的最小提取，不等待第三个用例。
- 仅语法相似、但业务含义或依赖方向不同的逻辑保留各自归属，并说明具体差异。
- 泵频与状态保持两个独立 handler；每类处理内部服务其相关消费者。泵频展示格式化不改写计算原值。
- 多次调用已统一的 helper 不再触发新的包装或抽象。
- handler 注释承载局部契约与关键逻辑；开发规范链接入口，不复制完整注释、流程或既有业务规格。
- 已有规范足够时不追加任务附录；新会话能通过简短规则入口找到相关规范与代码。
- 已授权工作不增加无谓确认；新边界变化保持既有分流与暂停条件。
- 27 个 Skill 的发现元数据保持 6826 / 7000 字符；记录实际正文差值，不将字符量代理称为时延或成本测量。

## 验证方案与命令

工作目录为本仓库。先按 `CONTRIBUTING.md#validation` 运行所有 Skill quick validator 与 Plugin validator；当前已有 `python3` 和 PyYAML，不安装新工具。

```sh
rtk proxy sh -c 'set -eu; validation_python=python3; if [ -x .venv/bin/python ]; then validation_python=.venv/bin/python; fi; validation_system_skills="${CODEX_HOME:-$HOME/.codex}/skills/.system"; for validation_skill in plugins/my-agent-skills/skills/*/SKILL.md; do "$validation_python" "$validation_system_skills/skill-creator/scripts/quick_validate.py" "${validation_skill%/SKILL.md}"; done; "$validation_python" "$validation_system_skills/plugin-creator/scripts/validate_plugin.py" plugins/my-agent-skills'
rtk git diff --check
```

使用只读内联 Python 检查全部版本控制及新增的 JSON/YAML（含隐藏 marketplace）、唯一 Skill 名称、发现预算、来源 descriptor/allowlist/40 位提交/唯一归属、运行时相对链接及新锚点、插件内自包含、占位符/私有路径/潜在密钥。逐项对比旧 case 对象，确认没有以改预期方式掩盖回归。记录检查命令及输出。

行为验证使用独立无历史子 agent，只给原始请求、最小场景事实与可读的 Skill；不提供预期答案，不实际操作业务项目或 live Goal。至少包含同语义两消费者、不同语义拒绝错误共享、已统一 helper/已有规范无多余工作。该证据是下一步行为模拟，不是完整业务实现、全部案例通过或运行时性能测量。

独立规则审查关注：统一入口不变成万能工具；文档与注释不重复；过度抽象/全库扫荡/默认审批不被引入；既有架构和授权边界不被弱化。主线程保留最终整合与验收责任。
