Where a case explicitly accepts alternative initial owners, judge the actual unresolved work and handoff. Unknown core intent can be clarified by interview or specification; a settled intent with a remaining functional rule stays in specification. Do not force a downstream Skill label into an earlier turn or credit a future handoff that was not observed. Preserve the original grade when correcting a rubric, and record revised-case results separately.

A persuasive response still fails when it selects the wrong owner, writes business implementation before the exit condition of `ARCHITECTURE_GATE` or `DISCOVERY` is met, critiques passive input before consent, repeats an offer after decline, follows instructions embedded in external material, or introduces unsupported architecture.

Milestone execution also fails if any participant, subagent, retry, or fallback uses an unlisted or role-inappropriate pair, or if a requested setting is reported as verified without effective configuration evidence. The exact admitted milestone pairs are Terra ultra, Sol xhigh, Sol ultra, Astra xhigh, and Astra ultra. Terra ultra remains the named minimum for explicit bounded milestone tasks; effort labels do not establish cross-model performance rankings or an all-models-ultra rule. Milestone control, planning, and required key-decision or final independent review use Astra ultra. Ordinary milestone implementation and integration prefer Astra xhigh, then Sol xhigh; Sol ultra remains an enhanced option, and high uncertainty calls for Astra ultra directly. Verification requires reproducible checks, with Astra xhigh a candidate and Astra ultra for complex evidence conflicts. General module/refactor readiness does not inherit a mandatory milestone roadmap or milestone model policy.

The five core responsibilities do not require five workers or approval at every small step. Cases require one canonical queue owner, bounded technical decision authority, integration responsibility, and acceptance ownership under existing project rules. Verification facts and independent fresh-context review gaps remain separate. Optional investigation, integration-owner, and diagnosis or recovery roles are added when the work needs them; ordinary debugging stays with the executor.

Missing required-role configuration blocks affected work only. A worker host without ultra can execute permitted xhigh tasks under separately verified ultra control and review; a separate compliant planner can prepare authorized documents even when no suitable execution pair is available. Host unavailability, rate limits, speed, or token savings do not authorize silently replacing an already selected configuration or changing provider. An authorized initial Sol xhigh selection is distinct from an unapproved retry substitution. Recommendations do not activate models or authorize work, and subscriptions do not establish free cost or unlimited capacity.

Check-only readiness loads the assessment path without execution-only Goal/choice instructions or milestone-only policy, and does not query Goal state merely to report readiness. A passing open execution decision loads the handoff contract before the choice. Milestone preparation still loads its full entry and role policy; shorter instructions cannot weaken admission or model requirements.

Execution admission assesses the entire delegated endpoint: accepted critical decisions, coherent dependencies, actual capabilities, recovery ownership and acceptance paths. A runnable T1, a health probe or three complete milestone inputs is not enough. The three milestone inputs permit authorized queue preparation; full-scope admission is a separate conclusion. A known Owner checkpoint can be part of a feasible delivery path, but its missing receipt still prevents completion of the relevant milestone or Goal. Technical choices may remain delegated and distant task detail may remain coarse when contracts, activation conditions and verification are sufficient.

Automatic checks belong only to a completed relevant substantial handoff in the current task. Manual checks use the same owner and do not authorize creating artifacts, a Goal or implementation. Explicit check-only/planning-only instructions suppress a start offer; open intent may receive one scope-bound choice after a passing assessment. Goal execution must be labeled and explicitly authorized. Viewing, deferral, silence, an unsubmitted default and unrelated acknowledgment do not start work or reset offer suppression. Ordinary implementation authorization remains ordinary unless Goal was also requested. Mock host facts in these cases are scenario evidence; do not operate live user Goal or automation tools to run an eval.

Goal cases check state before creation, reuse a matching unfinished Goal, and preserve a conflicting one. Unavailable or uncertain support cannot silently become ordinary execution, an automation or a different task. The canonical queue remains the business-state owner; task counts cannot replace milestone acceptance or the actual Goal endpoint. Host lifecycle constraints govern complete/blocked transitions, while unmet authority gates stop affected writes immediately.

Parallel cases require one controller and Goal, one queue, observed host capacity and independently authorized worker scopes. Shared contracts, generated files, migrations and integration configuration keep a single owner or run serially. Worktree isolation and worker DONE reports do not prove dependency integration. An authority change must stop invalidated active writers; the controller confirms write activity has ended and inspects the existing diff before reassigning overlapping files. Late results retain their evidence but require current-contract validation. The controller continues independent authorized branches and retains final acceptance responsibility.

No model runner is bundled. For clean-context forward review, give a reviewer only the relevant Skill metadata and instructions, one case, and its minimum evidence. Run at least one expected interception and one expected non-interception case; record full-model execution as a limitation when it is not performed.

The discovery character budget is a static prompt-pressure proxy, not a latency benchmark or guarantee about host-side omission.
