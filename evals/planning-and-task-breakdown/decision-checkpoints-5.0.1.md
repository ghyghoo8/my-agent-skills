## 最终规则

- 暂停前对比当前提案、已接受版本和实施授权。相同范围的接受跨回合有效；普通技术选择继续委托执行者。
- 改变业务含义、验收规则或架构边界的未决事项，在就绪准备阶段暴露。产品规则仍由需求流程处理；架构门禁保留原有四条路线及退出条件。
- 需要用户决定时，提供具体方案、变化、影响、有证据的推荐和一次范围明确的“接受／调整／暂缓”选择。证据不足时推荐具体补证；不武断推荐某个业务规则。接受仅绑定展示版本和已有授权。
- 继续独立获授权工作，复用待答问题和有效证据。无变化时不全量重读历史，不反复提问，不靠轮询或合成回合达到 blocked 条件。
- 仅在宿主条件满足时调用工具标记 blocked，并核对结果。恢复后保留交付终点和证据，按宿主规则重新计算阻塞审计。

这些规则澄清既有授权和门禁的应用，没有新增 Skill、触发范围、强制审批阶段、运行时 hook 或状态系统，因此使用 PATCH 版本 5.0.1。

## 行为验证方法

由独立 agent 增补案例，另用无历史上下文的 agent 读取 27 个 Skill 的发现元数据、宿主工具约束、一个原始场景，并自行选择所需指令。执行 agent 无权读取评分规则、其他案例或已有结果。独立评分者按冻结规则核对输出，主线程复核。

这是实际生成的**下一步行为模拟**：输出响应和拟调用动作，但不调用真实业务、提问、Goal、子 agent 或外部服务工具。未验证实际 UI、Goal 自动续接、业务写入或真实工具效果。运行继承宿主模型配置，没有独立证明其有效型号与推理档位，也不据此声称符合里程碑角色配置或跨模型稳定性。

冻结快照 A 覆盖前三个架构样本；B 补齐执行者和需求流程的引用入口后覆盖其余五个；C 仅修复就绪路径遗漏的推荐指示，重测同一个原始场景和评分规则。各快照保留文件哈希，证据按内容去重保存变更及实际读取的指令文本。最终源码与 C 对齐；前七个通过样本实际读取的指令在 C 中没有变化。
