# 5.0 执行交接交付验证

本次交付是 `my-agent-skills` 5.0.0 的源码、使用说明、行为契约和验证证据。开发就绪检查覆盖整个委托范围；手动检查与当前任务内自动交接共用一个入口，通过后优先提供明确标注 Goal 的执行选择。里程碑按交付验收节点定义，独立模块可由同一主控、Goal 和业务队列调度子 agent 并行执行。

这仍是 skills-only 工作流。自动发现、选择卡显示和 Goal 操作取决于宿主能力；本次没有安装、提交或发布插件，也没有以真实业务项目验证 5.0 的完整执行链。

## 交付入口

- [规划 Skill](../../plugins/my-agent-skills/skills/planning-and-task-breakdown/SKILL.md)：选择规划深度和当前工作阶段。
- [就绪评估](../../plugins/my-agent-skills/skills/planning-and-task-breakdown/references/execution-readiness-choice.md)：核对完整范围、实际能力、委托边界、恢复和人工介入点。
- [执行交接](../../plugins/my-agent-skills/skills/planning-and-task-breakdown/references/execution-handoff.md)：可复查的交付物链接、一次选择、Goal 创建/复用/冲突、执行中重评和验收。
- [并行协作契约](../../plugins/my-agent-skills/references/orchestration-patterns.md#parallel-module-execution)：独立写入与资源归属、依赖集成证据和主控验收责任。
- [原始验证证据](execution-handoff-5.0.0.results.json)：冻结输入与规则快照、实际输出、评分及哈希；保留失败和后续修正。

## 性能测量与优化

测量对象是按阶段需要读取的规则文本，以 Python `len(Path.read_text())` 计算 Unicode 字符数。对照基线是本次 5.0 功能完成、尚未优化加载方式的冻结快照，**不是已安装的 4.2，也不是模型速度对比**。

| 规则路径 | 优化前字符 | 最终字符 | 减少 |
|---|---:|---:|---:|
| 仅评估就绪：规划入口＋评估引用 | 25,789 | 18,135 | 29.68% |
| 普通模块完整启动：另按需读取执行交接 | 25,789 | 24,841 | 3.68% |
| 里程碑规划：入口＋里程碑引用 | 40,906 | 39,134 | 4.33% |
| 普通并行执行：执行 Skill＋共享协作引用 | 16,146 | 16,146 | 0% |

优化保留全部准入、授权、角色配置和验收要求，将仅执行时需要的选择/Goal 规则拆为一个条件引用，并删除入口中重复的里程碑细则。普通已授权执行直接复用有效任务卡；新的实质变化才触发受影响范围重评。

上述路径表不包含项目材料、系统指令和其他适用 Skill。发现元数据为 27 个 Skill 的名称＋description，共 **6,826／7,000 字符**，本次性能优化未改变它。若同样加上这段元数据及未改动的 Definition of Done（4,698 字符），仅评估路径为 **37,313 → 29,659 字符，减少约 20.51%**。

完整启动增加一个条件引用文件，字符缩减较小；文件数也不等同于工具调用回合数。因此不声称它降低了启动延迟。没有测量真实 token 消耗、耗时分布、费用或人工决策比例，没有新增缓存、遥测、运行脚本或依赖。

## 行为验证与修正记录

采用隔离的 fresh-context 下一步行为模拟：每个测试只接收 Skill 元数据、选定场景、最小原始项目观测及宿主工具契约，自行选择规则；不向执行者提供评分标准。输出描述拟执行的动作，未知工具返回值保持条件分支。独立评分核对授权、状态、依赖、验收和实际读取范围，不按固定措辞判定。

评测子 agent 未指定模型或 effort 覆盖，沿用宿主配置；没有独立核验其有效配置，不能用于模型优劣或速度结论。场景中的 C/W/R 配置回执只是该场景的输入事实。

首轮 9 个样例覆盖：自动选择、全范围缺口、条件授权启动、Goal 冲突、独立模块并行、待真人验收、执行中契约变化、人工入口和普通授权续跑。独立评分为 **8 PASS、1 FAIL**。FAIL 是选择前仅列文档名，未解析并展示交付物链接；执行授权边界本身通过。修正展示要求后另用新上下文复测，不改写原结果。

更早的选择工具校准输出因缺少准确组件参数记为 **INCONCLUSIVE**。随后向同一测试者补充实际工具契约，原输出单独保留；这次补充不算额外独立通过样例。

优化后另测仅评估、启动选择、条件 Goal 启动、缺少里程碑开发文档和普通续跑，五项按各自当时的 rubric 均为 PASS。就绪评估与里程碑入口的原有约束保留；选择样例补上实际路径解析与链接步骤。普通续跑虽然守住授权边界，却仍多读了就绪及 Goal 引用，因此单列性能问题，补充直接执行路由和加载约束后再次独立复测。

最终续跑复测独立评分 PASS，包含新增的加载约束。按测试者报告的实际读取文件清单，第一次优化样例读取 7 份运行规则、69,957 字符，最终样例读取 5 份、49,123 字符；后者没有加载就绪或 Goal 交接引用。两次均保持执行授权和验收要求。这个单样例包含其他 Skill 的选择差异，只说明该样例避免了多余读取，不代表总体成功率、token 或耗时改善。

首轮与后续样例均保留冻结输入。优化后的选择场景使用最终案例文件中明确给出的“当前无活动 Goal”观测；首轮场景则通过条件化 `get_goal` 获取该状态。这项输入差异有记录，不能将两次输出视为严格相同输入下的速度比较。

并行契约还经过独立静态审查，修复了在途任务的归属空隙：契约变化后，必须先通知或中断受影响 worker，确认停止写入并检查已有改动，才能重新分配相同文件。晚到结果保留为证据，但必须按当前契约重验；独立分支继续，任务成功声明不能替代集成或验收。

## 覆盖范围与静态检查

三个受影响案例集共 **129 条**：规划 53、发现 55、流程适度性 21。原始 27／49／17 条案例逐项与 HEAD 解析结果比较，保持不变；4.2 草案的 10 个选择案例保留 ID，本次另外补充 26 条契约。静态案例覆盖不等于 129 条均已运行。

本次有 15 次正式评分观察，覆盖 11 个不同案例 ID：14 PASS、1 个保留的修正前 FAIL；其中包含修正前后的重复样例，另保留一次不计入通过数量的工具校准结果。完整输出与逐项结论见原始证据，不能据此声称真实项目执行、宿主选项显示或真人验收已通过。

按 [CONTRIBUTING](../../CONTRIBUTING.md#validation) 执行所有 27 个 Skill quick validator 和插件 validator，使用现有 Python 3＋PyYAML；检查全部交付 JSON/YAML、隐藏 marketplace、上游映射与提交 ID、唯一 Skill 名、元数据预算、相对链接/锚点、未完成占位、私有运行路径、疑似密钥及 `git diff --check`，结果均为 PASS。静态检查的脚本、命令、实际结果和快照校验记录保存在原始证据中。最终回读还确认当前运行文件与最终冻结快照完全一致，所有内嵌快照内容符合记录的 SHA256。未改动无关的 `.codegraph/` 索引。

后续真实项目运行才能验证：自动触发命中率、宿主卡片显示、Goal 生命周期、并行 worker 停止确认与集成效果，以及意外人工介入和准备返工的实际频次。这些尚未执行的检查不计入本次交付通过结论。
