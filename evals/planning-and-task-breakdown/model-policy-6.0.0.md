# GPT-6 Sol Ultra 主控策略 — 6.0.0

按用户 2026-09-23 最后确认的要求定稿：**主控默认 GPT-6 Sol Ultra，交付质量第一；子 agent 的模型和推理强度由主控根据复杂度、风险和验收要求决定。** Sol 是常规模型上限，Astra 仅保留一次条件咨询。角色准入和模型证据的阻塞行为改变，因此使用 MAJOR 版本。

## 决策与取舍

- 不设固定的子 agent 强度白名单。medium、high、xhigh 是参考，困难 Sol 子任务可以使用宿主支持的 Max 或 Ultra。主控可以兼任规划，独立关键审查仍须独立上下文和责任。
- Luna 仅用于低风险、输入完整、结果可可靠验证的任务。质量或可验证性存疑时直接用 Sol；不强制先试低档，也不默认让 Sol 重做整份 Luna 成果。
- Ultra 可以使用子 agent。主控明确选择每个 worker 的设置，避免盲目继承、重复分派和争写同一资源；没有新增调度器或评分系统。
- Astra 必须在 Sol 实际尝试后仍存在实质性推理困境时，用于一次有界、只读、单 agent 咨询。整个已授权交付范围共用额度，由唯一队列记录授权来源和使用状态并预留；里程碑、worker、Goal 和上下文续接不重置额度。
- 缺资料、权限、环境故障或限流不构成升级理由。超时且启动状态不明时先核对回执，不自动重试；只有证明未启动才可释放预留。有效的既有条件授权无需重复确认。
- 咨询后由 Sol 评估、实现和验证。一次咨询不保证解决问题；未解决时保留阻塞、继续独立工作，额外 Astra 使用需要新的明确额度，不能降低验收标准。
- 宿主支持并保证明确选择时，可继续已授权工作并如实标记无法观察的实际生效设置。项目明确要求先有回执，或宿主无法保证选择时，才阻塞相关派发。Skill 不自行切换主任务模型或修改全局配置。

[官方模型指导](https://learn.chatgpt.com/docs/models)及[本周更新](https://learn.chatgpt.com/docs/whats-new#choose-gpt-6-sol-and-luna)，读取于 2026-09-23，介绍 Sol/Luna 定位、推理强度以及 Ultra 的子 agent 行为。主控 Ultra 是用户确认的工作策略，不是对模型能力或质量提升的测量结论。

[官方标准信用点费率](https://learn.chatgpt.com/docs/pricing#token-rates)为每百万 input / cached input / output token：Astra 250 / 25 / 1250，Sol 50 / 5 / 250，Luna 2.5 / 0.25 / 12.5。同类 token 单价为 Astra:Sol = 5:1，Sol:Luna = 20:1；这不是总任务成本、订阅额度或质量排名。一次咨询指一次有界 agent 回合，可能包含内部模型/工具调用，不是硬性货币预算。
